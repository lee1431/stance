# DDSM — Daily · Scan · Delivery

기존 DSD와 분리된 배송 작업용 실험 버전입니다. 휴대폰 번호 기반 로컬 작업과, 별도로 배포해야 하는 가입·로그인 API를 준비했습니다.

- 경로: `/ddsm/` (기존 `/dsd/`는 유지)
- 메인: **D** 날짜/회차, **S** 송장 바코드 스캔, **d** 배송시작
- 스캔: USB/블루투스 키보드형 바코드 리더, 번호 직접 입력, 브라우저 카메라(BarcodeDetector 또는 ZXing CDN 폴백)
- 배송 목록: 수취인/주소/연락처/메모 편집, 지도 검색 열기, 완료·완료취소·삭제
- 각 날짜·회차별 로컬 브라우저 저장, JSON 내보내기/복원
- 소스: `index.html`, `style.css`, `app.js`, `favicon.svg`.

## 중요 제약

인증을 우회하지 않습니다. 기존 DSD 서버에 연결하거나, 센터의 배송 원본 엑셀·배송 기사 계정·지도 API를 자동 조회하지 않습니다. 현재는 개인용 **localStorage 독립 실행형**으로, 기기간 자동 동기화도 없습니다. 브라우저 저장소를 삭제하거나 다른 기기를 쓰면 목록이 보이지 않으며, 백업 JSON에는 수취인 개인정보가 포함될 수 있으므로 안전하게 보관해야 합니다. 여러 탭에서 동시에 편집하면 마지막 저장이 우선될 수 있습니다.

배포는 정적 웹서버가 `/ddsm/` 하위 파일을 서비스하면 가능합니다. GitHub 저장소에 파일을 생성했다고 해서 `llsshh.com/ddsm/`의 서버 경로 설정까지 검증된 것은 아닙니다.

카메라 스캔에는 HTTPS, 카메라 권한이 필요합니다. ZXing CDN을 이용하는 브라우저는 인터넷 연결이 필요합니다. 카메라가 불가능하면 키보드형 스캐너/수동입력으로 사용할 수 있습니다. 실기 테스트는 별도 수행이 필요합니다.

추후 센터 자료와 서버 동기화를 연결하려면 공개 무인증 접근 대신 사용자/기기별 권한과 민감정보 보호 방안을 별도로 설계해야 합니다.

## 배송 지도 및 순번 편집 (2026-11-18)

- 배송시작/배송 목록 화면 **최상단**에 큰 NAVER 지도 배치. 태블릿·모바일 화면 크기에 맞춰 높이 조정.
- 지도는 선택 날짜의 **모든 회차 배송지**를 표시하고, 목록은 선택한 회차만 보여 줍니다.
- 번호 마커는 `회차 + 해당 회차 방문 순번`을 표시하며 배송 완료 여부에 따라 색상이 바뀝니다.
- 지도 마커 선택 → 해당 회차로 이동 → 배송 정보 수정. 상세 편집 지도는 기존처럼 중앙 고정 마커로 정밀 위치 보정.
- 목록에서 ↑, ↓, 순번 선택으로 방문 순서를 직접 편집. 로컬 저장 이후 지도 번호 즉시 반영.
- 저장된 좌표가 없고 주소가 있는 배송지는 지도 화면을 열 때 NAVER Geocoding으로 조회해 좌표를 로컬 저장합니다. 주소 미입력 또는 검색 실패 시 지도에 표시되지 않으며, `지도 표시 / 전체 / 위치 미확인` 건수를 확인할 수 있습니다.
- **전체 보기**로 표시된 배송지의 지도를 맞춥니다. 초기 위치가 여러 곳 조회되면 운전자가 지도를 직접 이동하기 전까지 범위를 갱신합니다.
- 경로 자동 최적화·도로별 경로선·서버 동기화는 이번 구현 범위에 포함되지 않습니다. 순번은 기사 수동 조정입니다.


## 휴대폰 번호 사용자 ID (2026-11-18)

- 최초 실행 시 본인 휴대폰 번호를 입력하면 이후 자동 선택됩니다. 초기화면의 번호 버튼으로 다시 확인하거나 변경할 수 있습니다.
- 기존 로컬 작업은 문자 인증·비밀번호 없이 동작합니다. 신규 가입·로그인은 별도 Flask API 배포 후 비밀번호로 인증하며, 현재 SMS 번호 소유자 검증은 없습니다.
- 이 브라우저에서는 전화번호별 localStorage 키로 배송 자료를 구분합니다. 번호를 바꾸면 해당 번호의 별도 자료가 열리고 이전 번호의 자료는 삭제되지 않습니다.
- 기존 단일 localStorage 배송 자료가 있으면 첫 전화번호 등록 때 복사해 이어서 사용하며 원본 데이터 키는 삭제하지 않습니다.
- 번호 자체가 서버 계정, 본인 인증, 공유 로그인 또는 장치 간 동기화를 제공하지는 않습니다. 실제 서버 동기화를 구현할 때는 별도의 인증과 데이터 접근 제어가 필요합니다.

## 신규 비밀번호 인증 API 준비

- 초기화면 DAILY 옆에 등록한 휴대폰 번호를 표시합니다.
- 사용자 화면에 전화번호와 비밀번호, 가입·로그인 버튼을 추가했습니다.
- `api/app.py`는 가입/로그인/세션 확인/로그아웃 API를 제공하며 서버 환경변수로 비밀키를 받습니다. 비밀번호는 scrypt 해시로 저장합니다.
- **저장소 반영만 완료**한 상태입니다. 실제 API 서버 배포, Nginx 프록시, SMS 본인확인과 배송 데이터 서버 동기화는 아직 필요합니다. 자세한 실행 조건은 `api/README.md`를 참고하세요.
- 기존 자료를 없애지 않기 위해 '서버 없이 이 기기에서 계속' 버튼을 유지했습니다. 이 모드는 서버 인증이 아닙니다.
