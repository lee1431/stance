# 배송 예정 · 완료문자

배송지 목록과 지도 카드의 `배송 예정`, `완료문자` 버튼으로 문자 작성 화면을 엽니다. 목록의 ⋯ 메뉴에서도 사용할 수 있습니다.

- 원본 엑셀의 수취인 연락처, 발송인, 물품명, 운임 구분, 운임 금액을 가져옵니다.
- 같은 회차에서 **전체 주소와 수취인 연락처가 모두 일치**하는 물품만 함께 선택할 수 있습니다. 주소만 같거나 연락처가 비어 있으면 묶지 않습니다.
- 배송 예정은 미완료 물품, 완료문자는 완료된 물품을 기본 선택합니다. 완료되지 않은 물품의 완료문자는 차단합니다.
- 착불만 합산합니다. 완료문자는 `수금 완료` 물품을 입금 요청에서 제외합니다.
- 원본 정보가 없으면 직접 입력합니다. 운임 구분·착불 금액·발송인·물품명·수취인 연락처와 필요한 입금 계좌가 확정되어야 문자 앱을 열 수 있습니다.
- 물품 정보와 연락처의 직접 수정은 이번 문자에만 적용됩니다. 원본 엑셀은 바뀌지 않습니다.
- 계좌·수금 여부·보관 장소는 `계좌·수금·장소 저장`으로 서버에 저장합니다. 문자 앱을 열 때도 저장합니다. 사진 공유 전 변경한 정보는 먼저 저장해야 합니다.
- 문자 내용은 수정할 수 있습니다. 다른 항목을 바꾸면 내용이 다시 생성되므로 마지막에 문구를 수정하세요.
- 문자 앱 열기·공유는 **실제 전송이나 배송 완료를 뜻하지 않습니다.** 배송 완료 처리는 기존 완료 버튼으로 합니다. 실제 전송 버튼은 기사가 문자 앱에서 누릅니다.

## 서버 업데이트

2026-11-17 센터 원본 정렬 v4 서버에 메시지 API를 추가한 `DSD_app_messages_v5_20261117.py`를 서버의 기존 `app.py`로 교체하고 기존 실행 방식으로 재시작해야 합니다. 기존 `run.py`, 환경변수, 의존 모듈과 데이터 경로를 유지합니다. 서버 중지 후 `app.py`와 데이터 폴더를 백업하세요.

추가 테이블은 `message_profiles`(기사별 계좌), `message_stop_state`(물품별 수금·보관 장소)입니다. 기존 배송지·센터·원본 테이블의 컬럼이나 데이터를 변경하지 않습니다.

인증된 API:

- `GET/PUT /dsd/api/message-profile`
- `GET /dsd/api/stops/<id>/message-data`
- `PUT /dsd/api/stops/<id>/message-state`

메시지 데이터 조회는 기존 원본 분석·운송장 조회 로직을 재사용합니다. 원본이 삭제되었거나 모호하면 직접 확인해야 합니다. 다른 기사나 접근 권한이 없는 센터의 물품은 조회·수정할 수 없습니다.

기존 서버에서 새 API가 404이면 직접 입력 모드로 열립니다. 이 경우 계좌·수금·보관 장소는 저장되지 않으며 화면에서 명시합니다. 브라우저 저장소에 고객 정보를 저장하지 않습니다.

## 사진과 휴대폰 확인 사항

완료문자에서 JPG·PNG·WebP 사진(최대 10MB)을 선택한 뒤 `사진과 내용 공유`를 누릅니다. Web Share를 지원하는 환경의 공유창에서 문자 앱을 선택하고 수취인 번호, 본문, 사진을 직접 확인하세요. 공유 대상·본문 전달은 OS와 문자 앱에 따라 다릅니다. 공유 완료 콜백도 발송 성공으로 기록하지 않습니다.

사진 공유 미지원 시 `내용 복사`와 `문자 앱 열기`를 사용하고 문자 앱에서 사진을 직접 첨부합니다. 사진은 DSD 서버에 업로드하거나 브라우저 저장소에 저장하지 않습니다. 사진은 MMS, 긴 내용은 LMS가 될 수 있으므로 기사 요금제를 확인하세요.

안드로이드 웹뷰는 네이티브 쪽에서 `sms:` 외부 앱 연결을 지원해야 합니다. 이 저장소에는 설치형 안드로이드 앱의 소스가 없어 APK는 변경하지 않았습니다. 웹뷰에서 막히면 우선 휴대폰 크롬에서 이용하세요. iOS와 안드로이드의 실제 문자 앱 전환·본문·사진 전달은 실기기 확인이 필요합니다.

## 검증

저장소 루트에서 `node dsd/tests/message-tools.test.cjs`로 금액 파싱, 선불 제외, 착불 합계, 수금 제외, 계좌 누락, 연락처 검증, 플랫폼별 문자 링크를 확인합니다. 서버 API는 SQLite로 소유권·물품 묶기·설정 격리·수금 저장·입력 검증을 확인했습니다(원본 조회는 고정 데이터 대체). 서버 파일의 Python 컴파일 검사를 통과했습니다. 휴대폰 실발송은 수행하지 않았습니다.
