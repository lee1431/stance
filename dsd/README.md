# 배송지도 웹 프론트엔드

## 원본 엑셀 직접 가져오기 (2026-11-10)

- /dsd/ → 코스 만들기 → 원본 엑셀 업로드. .xlsx, .xls, .xlsm 파일을 파일 변환 없이 선택합니다. SheetJS 파서는 사용자가 파일을 선택한 뒤 브라우저에 로드됩니다. 원본 워크북은 서버에 업로드하지 않습니다.
- 시트 선택, 제목 행 선택(자동 추정), 배송지 주소/고객명/상세주소/송장번호/수량 열 매핑, 최대 5개 행 미리보기를 제공합니다. 업로드는 최대 10MB, 1회 500 배송지로 제한합니다.
- 선택된 날짜/회차에 추가하며, 기존 배송지를 덮어쓰지 않습니다. 송장번호가 같은 기존 행만 중복으로 건너뛰고, 주소가 같더라도 송장이 다르면 별도 배송건으로 유지합니다. 원본 파일명·시트명·행 번호를 각 배송지에 기록합니다.
- 좌표 변환은 현재 연결된 NAVER Maps Geocoder를 통해 건별 수행하며, 코스 저장 스냅샷에 성공 건을 함께 기록합니다. 주소 검색 실패 건과 주소 없는 행은 실패 목록 CSV로 다운로드합니다. 일부 행이 실패하더라도 성공 행은 저장됩니다.
- 현재 브라우저의 localStorage에만 고객 정보가 남으며 UVB 백업은 별도입니다. 실기 테스트, 네이버 주소 검색 호출 제한 및 대량 업로드 성능은 별도 검증이 필요합니다.
- 외부 SheetJS CDN이 차단된 네트워크에서는 파일을 읽지 못합니다. 공개 서비스에서 운영하려면 라이브러리를 정적으로 자체 제공하고 라이선스·무결성을 검토해야 합니다.


현재 경로: `stance/dsd/`.

## 구조

- `index.html`: 데스크톱 배송 작업 공간 및 모바일 지도·목록·주소 추가·설정 화면
- `style.css`: 반응형 화면 구성과 고객명 마커 스타일
- `app.js`: 네이버지도 SDK, 배송 완료 마커 토글, 목록 검색/필터, 로그인 계정·관리자 기능
- `login.html`: 기존 Flask/Jinja 로그인 템플릿. **정적 서버에서 그대로 서비스하면 Jinja 문법은 렌더되지 않음**

## 저장된 배송 코스의 도로 경로선 복원 (2026-11-10)

- **코스 저장**은 서버 호출 없이 현재 브라우저에서만 실행하며 편집 패널을 닫지 않습니다. `dsd:center:<center-id>:round:<round-id>:saved` 스냅샷에 배송지, 방문 순서, 마지막 고정과, 현재 OSRM에서 확보한 도로 좌표(`road.path`), 거리(`road.meters`), 시간(`road.seconds`)을 함께 기록합니다.
- 왼쪽 **저장된 코스 → 1회차 코스**를 누르면 스냅샷 배송지/순서를 복구하고 도로 좌표가 있다면 서버 요청 없이 지도에 실선으로 표시합니다. 지도 범위도 주행 경로를 포함하여 맞춥니다.
- 기존처럼 도로 좌표가 없던 스냅샷은 방문 순서를 변경하지 않고 `DsdRoad.geometry(...)`로 실제 도로 선만 조회합니다. 외부 OSRM 테스트 서버로 좌표를 보내는 경우 반드시 브라우저 동의 정책을 따릅니다. 성공 시 스냅샷에 경로를 캐시해 다음번에는 별도 도로 API 요청 없이 보여줍니다. 실패/거절 시 가짜 직선 경로를 표시하지 않습니다.
- 저장본에 경로선이 없던 경우뿐 아니라 **임시 회차를 눌렀을 때에도** 해당 방문 순서에 대한 도로 경로선만 조회해 보여줍니다. 이미 저장된 경로선은 페이지 초기화 시에도 다시 복원됩니다.
- 회차 선택/저장과 **UVB 백업**은 별개입니다. UVB 백업은 선택적으로 암호화해서 시도하고 서버 저장 성공 여부는 재조회로 확인해야 합니다.
- 레거시 경로가 없는 16개 초과 배송 코스는 공개 OSRM 시험 서버에서 경로 조회하지 않습니다. 정식 서버 도로 API가 필요합니다.

## 날짜별 배송 회차 · UVB 암호화 저장 (2026-11-10)

**업무 단위:** 한 센터의 특정 날짜에 대한 1회차, 2회차, 3회차, … N회차. 회차마다 서로 다른 배송지·순서·정차점·기사 메모를 보유합니다. 회차가 달라지면 다시 계산한 임시 코스를 보여줄 수 있지만, UVB에 저장된 회차는 사용자가 불러와 변경하지 않는 한 수정하지 않습니다.

### UI / 브라우저 임시 저장
- 코스 만들기 → 배송일 선택 → 회차 선택 또는 `+ 회차`로 해당 날짜의 다음 번호 생성. 같은 날짜에 4회차 제한 없음(상한 1,000,000).
- 기존 코스는 첫 실행 시 현재 한국 날짜의 1회차부터 순서대로 기존 센터/코스 ID를 보존하여 이관합니다. 원래 `dsd:center:<center-id>:stops` 키는 삭제하지 않고, 각 회차에 별도 사본을 만듭니다.
- 이후 배송지는 `dsd:center:<center-id>:round:<route-id>:stops`에 회차별로 분리해 임시 저장합니다. 방문 순서/고정 방문은 기존 `dsd:center:<center-id>:route:<route-id>` 키를 그대로 사용합니다.
- 기존 서버 저장본은 별도 'UVB 조회' 버튼 또는 코스 창 열기 시 목록을 확인할 수 있습니다. 서버 기록을 고르면 **암호 입력 후** 해당 회차의 배송지와 순서를 불러옵니다. 이미 같은 날짜·회차에 브라우저 임시 데이터가 있다면 덮어쓰기 전에 확인합니다.
- `로컬 삭제`는 브라우저 임시 데이터만 삭제하며 UVB 기록을 삭제하지 않습니다.

### UVB 저장 형식 / 한계
- 실제 확인된 읽기 URL은 `https://localflow.ddns.net/uvb/v1/apps/dsd/items?page=1&page_size=10&order=desc`입니다. **2026-11-10 UVB 관리자 앱 목록에는 `dsd` 등록이 확인되지 않았습니다.** GET에서 빈 목록이 나오는 것만으로 POST 저장 권한이 있다는 뜻은 아닙니다. 서버에 앱 등록과 접근 통제 설정이 필요할 수 있습니다.
- 저장 후보 URL은 이미 사용 중인 UVB 패턴의 `POST https://localflow.ddns.net/uvb/v1/apps/dsd/items`입니다. 이 앱에 대한 실제 POST 허용·성공 여부는 **미검증**입니다. 실패하면 화면에서 실패로 표시하고 기존 로컬 데이터만 유지합니다.
- `round-storage.js`는 고객 이름/주소/좌표/출입 메모/순서를 전부 **AES-256-GCM**으로 암호화한 `sealed` 필드만 서버로 전송합니다. 비밀번호를 저장하거나 서버에 보내지 않습니다. PBKDF2-SHA256(250,000회) 사용. 암호 분실 시 서버 저장 데이터를 복구할 수 없습니다.
- 평문 메타데이터는 `kind`, `date_key`, `round_no`, `center_id`, `center_name`, `snapshot_id`, `saved_at`뿐입니다. 센터명과 날짜/회차가 공개된다는 점도 검토해야 합니다.
- `UVB 저장`은 append-only 버전으로 POST한 뒤 전체 페이지 재조회에서 `snapshot_id`를 확인했을 때만 성공으로 처리합니다. 불확실한 POST는 자동 재전송하지 않으므로 중복 생성을 피합니다. 같은 날짜·회차의 이전 버전은 남습니다.
- 이 방식은 **기밀성 확보를 위한 시험 구현**이며 **권한 통제를 대체하지 않습니다**. UVB 서버에서 사용자 인증, 센터 접근 권한, 저장 충돌 감지, 백업과 서버 접근 감사를 구현해야 실제 고객 정보 저장에 적합합니다. 브라우저 localStorage에는 배송지 원문이 남으므로 공유 PC 사용에 주의해야 합니다.

## 현재 배포되는 /dsd/ 화면 (중요)

GitHub Pages의 `dsd/index.html`은 **독립형 브라우저 저장 버전**입니다. 아래에 설명하는 `dsd/app.js` 및 S21 Flask API 방식은 별도의 서버 연동용 코드이며, `index.html`에는 자동 적용되지 않습니다.

### 센터별 코스 v1 (브라우저 저장)

- 화면 왼쪽 상단의 **센터 선택 / + 센터**로 센터를 만들고 바꿀 수 있습니다.
- 센터마다 등록 배송지, 코스 목록, 코스별 방문 순서가 독립적입니다.
- **코스 만들기** → 코스 선택·추가·이름 변경·삭제 → 배송지 추가·제외 및 순서 조정 → **코스 저장**.
- 코스 삭제는 배송지를 삭제하지 않습니다. 배송지를 삭제하면 해당 센터의 다른 저장 코스에서도 삭제된 배송지 참조를 정리합니다.
- 이전 버전의 `dsd:vanilla:stops:v1`와 `dsd:vanilla:course:v1` 값은 첫 실행 시 **기본 센터**로 복사하며, 원래 값은 복구용으로 그대로 둡니다.
- 센터 목록은 `dsd:centers:v1`, 배송지 목록은 `dsd:center:<center-id>:stops`, 코스는 `dsd:center:<center-id>:route:<route-id>`로 각각 `localStorage`에 저장됩니다.

**한계 및 데이터 보안:** 이 기능은 같은 브라우저·프로필에서만 유지됩니다. 기기 간 동기화, 센터별 사용자 접근 권한, 서버 백업은 아직 없습니다. 브라우저 데이터 삭제·프로필 변경 시 자료가 없어질 수 있습니다. 같은 브라우저를 쓰는 사용자는 다른 센터의 자료에도 접근할 수 있으므로 **인증된 멀티센터 운영 환경으로 간주하면 안 됩니다.**

### 도로변 접근·정차점·마지막 방문 고정 (2026-11-09)

`dsd/index.html`에 현장 배송 지식 기록 기능을 추가했습니다.

- 지도에서 배송지 마커 선택 → **현장정보** 또는 **코스 만들기 → 상세**에서 접근 정보를 수정합니다.
- 배송지마다 `approachHint` (길 건너편, 진행 방향 도로변, 유턴, 일방통행, 별도 출입구), `accessNote` (기사 메모), `parking: {lat,lng}` (선택한 정차점)을 센터별 배송지 객체에 저장합니다.
- **지도에서 정차점 선택**을 누른 후 지도 배경을 클릭하면 건물 좌표와 별도로 정차점을 저장하며, 지도에 `P` 마커가 표시됩니다. 정차점 해제도 가능합니다.
- 코스 목록의 **📌** 버튼은 해당 배송지를 **마지막 고정** 구간으로 옮깁니다. 여러 곳 고정 시 목록에서 정해진 순서대로 마지막에 유지됩니다. `↑↓` 버튼으로 같은 고정 그룹 안의 순서만 변경할 수 있습니다.
- `가까운 순 추천`은 고정 배송지를 제외한 나머지의 방문 순서만 계산하고, 고정 배송지를 마지막에 붙입니다. 코스별 `pinnedLastIds`를 기존 `ids`와 함께 저장합니다.
- 직선 연결거리와 지도 선은 건물 좌표 대신 지정된 정차점을 기준으로 표시합니다. **도로망·일방통행·실제 주행 경로 최적화는 아직 구현되지 않았습니다.** 정차점은 주차 가능 여부를 보장하지 않습니다.
- 실측된 운전 지식이 아니라 기사 수동 기록값이며, 현 단계에서는 브라우저에만 보관됩니다. 서버 접근 권한과 공유 기능은 별도 구현해야 합니다.

### 코스 자동 편성 기본 동작 (2026-11-10 수정)

- **코스 만들기**를 열면 저장된 수동 코스(`orderMode: manual`)가 아닌 경우, 추가 버튼을 다시 누르지 않아도 브라우저 안에서 정차점 좌표 기반 근거리 방문 순서를 즉시 계산합니다. 예전 저장 코스 중 `orderMode`가 없는 코스는 **미리보기에서만** 자동 정리합니다. 저장 전 기존 기록은 그대로 둡니다.
- **전체 추가** 버튼도 추가한 배송지를 즉시 근거리 순서로 재배치합니다. 배송지 추가·제외·마지막 고정 변경은 자동 코스에서는 재계산하며, 기사님이 위/아래로 직접 순서를 바꾼 뒤에는 그 **수동 순서를 저장하고 다음에 열어도 보존**합니다.
- 처음 도로망 자동 추천을 실행할 때 **외부 OSRM 서버에 좌표를 공유할지 사용자에게 한 번 확인**하고, 동의한 브라우저에서만 이후 코스를 열거나 다시 구성할 때 자동 도로 추천을 실행합니다. 거부하면 브라우저 내부의 **근거리 초안**만 사용합니다. 언제든 '도로 기준 재추천 (시험)' 버튼을 누르면 도로망 추천을 다시 요청할 수 있습니다.
- 도로망 계산에 실패하면 근거리 초안이 남지만, **실제 도로가 아닌 직선 연결선을 지도에 그리지 않습니다.** 신뢰할 수 있는 도로 형상이 반환된 경우에만 주행 도로 선을 그립니다. 근거리 참고거리는 주행거리로 취급하면 안 됩니다.
- 저장 데이터에 `orderMode` (`manual`, `auto-air`, `auto-road`)를 추가하되 기존 `ids`와 `pinnedLastIds`를 유지합니다.

### 도로 기준 코스 추천 시험 기능 (2026-11-10)

- `/dsd/`에서 **코스 만들기 → 도로 기준 추천 (시험)**을 선택하면 별도 확인 후 OSRM 공개 데모 서버에 **정차점 좌표 및 GPS 출발점 좌표**를 전송합니다. 고객 이름·상세 주소 문자열은 전송하지 않지만 좌표로 주소나 고객 위치가 추정될 수 있습니다. 민감한 실제 고객 배송지 데이터로 시험하지 마세요.
- `road-routing.js`는 공개 OSM 기반 자동차 도로망의 **방향별(distance/duration) 거리 행렬**을 받아 초기 방문 순서를 만들고 방향성 비용으로 2-opt 개선합니다. 기존 마지막 고정 순서는 보존합니다. GPS가 없으면 현재 코스의 첫 일반 배송지를 고정 출발점으로 삼습니다.
- 추천 직후 도로 거리/예상 시간(교통 미반영)과 실제 자동차 경로 선을 표시합니다. 경로 선 조회가 실패하면 직선 점선으로 남고, **실제 도로 경로로 오인하면 안 됩니다**. 조회 실패 시 기존 방문 순서를 유지합니다.
- 공개 OSRM 데모는 **시험용**으로만 사용합니다. 출발점 포함 최대 16곳으로 제한하며 대량 상용 배송, 서비스 가용성, 한국 도로 최신성, 주정차·차량 제한·실시간 교통 반영을 보장하지 않습니다. 브라우저의 CORS/서비스 정책/망 문제로 요청이 실패할 수 있습니다.
- 출발점·코스·센터·정차점 정보가 바뀌면 도로 미리보기는 무효화됩니다. 기존 센터·코스 localStorage 저장 형식과 마지막 고정 데이터는 그대로 유지합니다.
- 실제 운영에서는 인증된 서버에서 NAVER 길찾기 등 정식 계약 API를 호출하거나 자체 도로 엔진을 운영해야 합니다. **API 비밀키는 정적 사이트에 저장하지 마세요.**

### 여러 기기에서 공유하는 서버 저장을 위한 후속 작업

S21 Flask와 SQLite 소스가 이 저장소에 포함되어 있지 않아 기존 인증·DB 스키마와 호환되는 서버 코드 배포는 여기서 검증하지 못했습니다. 서버 단계에서는 다음과 같이 확장해야 합니다.

1. `centers (id, name)`, `center_members (center_id, user_id, role)`, `routes (id, center_id, name, updated_at, revision)`, `route_stops (route_id, stop_id, position)` 테이블을 운영하고 배송지에도 `center_id`를 부여합니다.
2. 매 요청에 현재 로그인 사용자의 센터 소속·역할을 검증하고, 조회·수정·삭제 조건에 **항상 센터 ID**를 포함합니다. 클라이언트에서 보낸 센터 ID만 신뢰하면 안 됩니다.
3. 코스 변경 시 트랜잭션 및 `revision` 검사로 동시에 수정하는 기사 간 데이터 충돌을 처리합니다. 정기 백업을 구성합니다.
4. 기존 데이터 이관 시 사용자·센터 매핑을 확인하고, 데이터를 공개 API나 GitHub Pages 정적 파일에 넣지 않습니다.

## 백엔드 연결

서버 연동형 `app.js`는 갤럭시 S21 Flask v0.6과 SQLite DB를 전제로 합니다. **현재 배포되는 `index.html`은 이 백엔드를 사용하지 않고 브라우저에 저장하므로 혼동하지 마세요.**

브라우저가 `https://llsshh.com/dsd/`로 접속하면 다음 **동일 출처 요청**이 Flask로 전달되어야 한다.

- `/dsd/api/auth/me`, `/dsd/api/auth/logout`
- `/dsd/api/stops`, `/dsd/api/stops/completed`, `/dsd/api/stops/<id>`, `/dsd/api/geocode`
- `/dsd/api/config`, 관리자용 `/dsd/api/users`
- `/dsd/login` 및 로그인 POST 처리

단순히 `app.js`의 fetch URL을 S21 도메인으로 변경하는 것은 적절하지 않다. Flask 세션 쿠키가 서로 다른 도메인에 공유되지 않기 때문이다. `llsshh.com`에서 동일 출처로 보이도록 **서버측 reverse proxy**가 필요하다.

HTTPS Nginx 리버스 프록시 설정 예시 (기존 서비스와 경로 충돌 여부 확인 필수):

```nginx
location ^~ /dsd/api/ {
  proxy_pass https://localflow.ddns.net/dsd/api/;
  proxy_set_header Host localflow.ddns.net;
  proxy_set_header X-Forwarded-Proto https;
}
location = /dsd/login {
  proxy_pass https://localflow.ddns.net/dsd/login;
  proxy_set_header Host localflow.ddns.net;
  proxy_set_header X-Forwarded-Proto https;
}
```

**주의:** 로그인 POST의 리다이렉트 `Location`, Flask 쿠키 Path/Domain, CSRF 검증, 프록시의 SSL 및 웹 호스트 검증을 실제 환경에 맞게 확인해야 한다. 위 예시는 배포 확인 없이 그대로 적용할 수 있는 확정 구성이 아니다.

네이버 클라우드 Maps Web 서비스 URL에도 **`https://llsshh.com`**을 추가 등록해야 한다. Client Secret을 프론트에 넣지 않는다.

## UI 동작

- PC: 지도와 사이드바를 동시에 표시하고 탭으로 배송 목록/주소 등록/계정 설정을 전환.
- 모바일: 지도가 기본 화면, 하단 메뉴에서 배송 목록·주소 등록·설정 패널 표시.
- 마커 클릭 시 배송 완료 상태 저장.
- 완료건 일괄 삭제는 **본인 완료 건만 삭제**하고 미배송은 보존하도록 서버 API `DELETE /api/stops/completed` 사용.
- 배송지 검색과 상태 필터는 현재 계정 목록에 대한 **프론트 화면 표시 필터**이며, 서버 권한 검사를 대체하지 않음.
